### AI OUTPUT THAT WAS WRONG:
The initial SLA calculation function generated by the AI used a naive time-difference check:
```typescript
// AI's flawed initial code:
const isBreached = Date.now() - new Date(ticket.createdAt).getTime() > ticket.slaResolutionHours * 3600000;
```
This naive logic caused three major defects:
1. It completely ignored tickets that were already resolved on time, falsely flagging them as "Breached" if inspected days later.
2. It failed to halt when a ticket entered `PENDING_STUDENT_ACTION`, unfairly causing tickets awaiting police lost reports to breach in the background.
3. It had no mechanism to extend the deadline when the student finally uploaded documents.

---

### HOW I IDENTIFIED THE PROBLEM:
While testing the ticket workflow with pre-seeded data, I noticed that `TKT-2026-1028` (a bonafide certificate request resolved in under 24 hours, well within its 120-hour SLA) was falsely showing up with a red "Breached" badge. Additionally, when I moved a ticket to "Pending Student Action", the SLA countdown timer continued ticking down, which violated the institutional requirement.

---

### HOW I FIXED IT:
1. Replaced the static timestamp check with state-aware SLA evaluation in `slaCalculator.ts`:
   - For `RESOLVED` / `CLOSED` tickets, compare `resolvedAt` against the effective deadline.
   - For `PENDING_STUDENT_ACTION`, set status explicitly to `PAUSED`.
   - For active tickets, compute the effective deadline by adding `totalPausedMinutes * 60 * 1000` to the original deadline:
   $$\text{Effective Deadline} = \text{slaDeadline} + (\text{totalPausedMinutes} \times 60 \times 1000)$$
2. Updated the status transition handler in `TicketContext.tsx` to automatically capture `slaPausedAt = new Date().toISOString()` when pausing, and calculate elapsed minutes to add to `totalPausedMinutes` upon resumption.
